# Contributing to Thock

Thanks for helping. Bug reports, fixes and sound packs are all welcome. For a new feature, open an issue first so we can agree on the scope before you write code.

By taking part, you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Setup

- macOS 14 or later, Xcode 27 and XcodeGen (`brew install xcodegen`). There are no other dependencies.
- `project.yml` is the source of truth. `Thock.xcodeproj` is generated by `make` and never committed.
- DerivedData lives in `~/Library/Developer/Xcode/DerivedData/Thock-make`, outside the repository.

```sh
make build              # generate the project and build build/Thock.app
make run                # build, quit the running copy, launch the new one
make test               # unit tests
make logs SINCE=5m      # Thock's log, TCC decisions and sandbox denials
make shots              # render the menu and settings to PNG without launching the app
make render PACK=cream  # render a typing sequence offline and print timing and clipping figures
```

The default build is signed ad hoc, so macOS asks for Input Monitoring after every rebuild. To keep the permission, set a stable identity in `Config/Signing.local.xcconfig` (ignored by git), as described in the README's Signing section.

Every log line uses the subsystem `io.github.dailyxplorer.thock`. `AppIdentity.subsystem` must stay equal to the bundle identifier so `make logs` finds them.

## Tests

- `make test` runs the Swift Testing suite in `Tests/ThockCoreTests`. It must pass, and `make build` must print no warning.
- A bug fix comes with a test that fails without the fix. Test behavior through the public API, with literal expected values.
- The input and audio paths are tested for zero allocations. Keep it that way.
- Changes to permissions, devices, sleep or the UI can't be fully unit tested. Run the matching checks in [MANUAL_TESTS.md](MANUAL_TESTS.md) and say which ones in the pull request.

## Code style

- Swift 6 with strict concurrency, SwiftUI and AppKit, no third-party dependencies.
- No comments in code. Pick names that explain the code. Put the reasoning behind a design in the README or in the pull request.
- Everything in English: identifiers, UI strings, logs, errors, docs and commit messages.
- Privacy is a feature. Never log a keycode or typed text, never add network access, never store input.
- Match the surrounding code. Don't reformat or refactor code your change doesn't need.

## Sound packs

Most packs don't need a pull request: share the folder, and anyone can import it from Settings > Packs. A pack is a folder with:

- `pack.json`: `{"name": "…", "author": "…", "license": "…", "source": "https://…"}`. `source` is optional.
- Audio files named `category_direction_variant` (`alpha_down_1.caf`) or `category_direction_rROW[_variant]` (`alpha_down_r2.caf`, rows 0 to 4). Categories are `alpha`, `space`, `enter`, `backspace`, `tab`, `modifier`, `arrow`, `punctuation` and `mouse`. Directions are `down` and `up`. At least one `alpha_down` file is required.
- Formats: `caf`, `wav`, `aiff` or `aif`. Bundled packs use 16-bit mono CAF at 48 kHz: `afconvert -f caff -d LEI16@48000 -c 1 in.wav out.caf`.

To propose a bundled pack:

- You must have the right to redistribute every file under a license compatible with MIT redistribution (CC0, CC-BY 4.0, MIT or similar). Recordings of your own keyboard are ideal. Never submit sounds taken from another app.
- Put the folder in `Sources/Thock/Resources/Packs/<id>/`, with the license text in `LICENSE.txt`.
- Credit the source in `THIRD-PARTY-LICENSES.md` and in the README's pack table.
- Add the id to the bundled pack lists in `Tests/ThockCoreTests/PackLoaderTests.swift` and `PackLibraryTests.swift`, then run `make test` and `make preview PACK=<id>`.

## Reporting bugs

Open an issue with the bug report template and include:

- macOS version and Mac model.
- Thock version or commit, and how you built it.
- Keyboard (built-in or external, ANSI or ISO, layout) and audio output (speakers, wired, Bluetooth).
- Steps to reproduce, what you expected and what happened.
- The counters from Settings > Diagnostics and the output of `make logs`, if relevant. Neither contains keycodes.

Report security issues privately, as described in [SECURITY.md](SECURITY.md).

## Commits and pull requests

- Keep pull requests small and focused on one change.
- Write commit subjects in the imperative, under 72 characters ("Fix stuck Shift after wake"). Use the body to explain why.
- Update the README or `MANUAL_TESTS.md` when behavior changes. For UI changes, attach before and after screenshots (`make shots`).
- Fill in the pull request template.
